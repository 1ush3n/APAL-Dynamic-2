### W3-07：有符号时间残差与共享辅助监督

**目标：** 修复F06，使时间头能纠正启发式高估和低估。

**涉及文件：**

- 修改：`models/work3/time_head.py`
- 修改：`models/work3/train_time_head.py`
- 修改：`models/work3/ppo_trainer.py`
- 新增测试：`tests/work3/test_work3_f06_signed_time_residual.py`

**修改方式：**

1. 时间头输出`delta ∈ R`，删除输出端`ReLU`和只保留正残差的门控回归限制。
2. 保留最终物理边界：`P_hat = max(current_time, P_h + H0 * delta)`。
3. 正负标签全部进入Huber或均方回归。
4. 时间头输入改为Actor共享图表征；PPO总损失增加`lambda_time * L_time`。
5. Critic仍预测综合回报，不把时间预测当作Critic替代品。

**验收：** 正残差和负残差均可拟合；只反传时间损失时，共享图编码器和时间头都有梯度。

## 每个任务的固定执行模板

### 1. 开始前

- 在本文件对应任务下填写本次目标、涉及文件和假设。
- 检查`git status --short`，确认无关修改清单。
- 阅读相关确认稿和现有调用者，先追踪根因，不先改生产代码。

### 2. 红：先写反例/测试

- 新增最小测试或修改冲突测试。
- 使用`rag_env`运行单个测试。
- 必须观察到预期失败；若测试直接通过，说明测试没有覆盖问题，先修测试。
- 将失败命令、失败断言和失败原因写入任务记录。

### 3. 绿：最小修改

- 只修改当前任务所需文件。
- 保留已有接口时优先替换内部算法，不无理由重写动作架构。
- 不在同一提交中顺手修复其他F项。

### 4. 验证

- 重新运行当前任务测试。
- 运行受影响的工作三回归测试。
- 运行对应独立小案例或真实小规模轨迹。
- 检查失败率、可行性、原始费用和日志，不只看pytest数量。

### 5. Git提交

只暂存当前任务相关文件：

```text
git add <当前任务测试文件> <当前任务源码文件> <本记录文件>
git diff --cached --check
git commit -m "fix(work3): <任务编号> <简短中文描述>"
```

提交后将提交号、测试命令、结果、独立案例结果和未解决事项写回本文件，再开始下一个任务。
