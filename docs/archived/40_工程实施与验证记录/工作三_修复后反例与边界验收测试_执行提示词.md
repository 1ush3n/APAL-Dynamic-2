把本文件完整交给代码助手。先执行第1节总提示词，再按第3—16节分组实施。每组包含可直接执行的构建要求和独立测试用例；不要一次性生成大量只验证字段存在的空测试。

## 9. G组：异构图、条件概率与PPO重放（F05及动作架构）

**构建提示词：** 使用小图、固定模型、固定采样记录验证数值；不要以一次随机训练损失下降作为概率正确性的证据。临时关闭dropout或固定其评估语义，记录归一化模式。自回归团队的抽样顺序与执行中的无序团队需分别保存。

| ID | 构造/操作 | 期望 |

| G01 | 从真实训练入口执行一个采样和更新 | 图构造→图编码→任务/工人表示→动作头可追踪；并非仅调用未使用的图函数 |
| G02 | 独立反传非退化策略损失 | 至少一组应共享的图参数梯度有限且非零；不强求所有层每样本都有非零梯度 |

| G04 | 只改具体工人日历/技能/基准团队关系 | 对应图特征或边变化并能送达选人头；不要求随机策略必换动作 |
| G05 | 增加尚未入线未来飞机 | 当前周期实际负荷不混入其工作量；未来负荷可在单独特征中改变 |
| G06 | 同一参数、同一快照：采样后evaluate_actions | 新旧联合logprob在FP32容差内一致，ratio≈1，任何分支都测 |
| G07 | 后移分支 | logprob仅任务+站位；未激活选人/对齐头不计概率或熵，不因DUMMY字段变化而改变 |

| K15 | 自主空线控制模式（如选择） | 用实际日志验证暖机条件，不能用固定5H0代替；同一外生事件与暖机规则的冲突明确报告 |
| K16 | 相同种子与配置重复生成清单 | 内容一致；不同种子不要求任意两条都不同，但应无全局随机源遗漏 |
| K17 | 配置中强度为H0比例，导出报告 | 同时记录比例及实际小时；不能写成另一套5—60h设置 |
| K18 | 评测决策上限提前退出且费用很低 | 明确失败/截断，不能把低费用当作方法优越 |

A/B/E/F/G尚未到实施阶段时报告NOT_RUN及阶段，不以“可配置接口已存在”替代实际执行覆盖。

用户于2026-09-25确认采用统一基准暖机前缀；K14须按真实站位和同步转站日志验收，K15记`NOT_APPLICABLE`。固定外生事件不得因暖机而移动；若事件时刻早于暖机完成时刻，应明确报告协议冲突。

## 14. L组：终止、截断、GAE及异常（F11）

**构建提示词：** 用确定奖励和值函数的小序列手算TD残差和GAE。至少验证正常终止、继续采样的段截断、需要reset的时间截断、真实失败终止四种路径。

| ID | 序列 | 期望 |
|---|---|---|
| L01 | 正常最后一步r=2、V=1，真实终止 | TD残差=1，后继值0；success还需独立可行性通过 |
| L02 | r=2、V=1，非终止段尾V_next=4，γ=0.9 | TD残差=4.6，不能误用终止结果1 |
| L03 | 两步非终止：r=[1,2]，V=[0.5,1]，尾值3，γ=.9、λ=.8 | δ=[1.4,3.7]，A1=3.7，A0=4.064 |
| L04 | L03第二步改成真实终止 | δ1=1，A0=2.12；与非终止分开 |
| L05 | 一个采样段包含前一episode结束和下一episode开始 | GAE不跨真实终止传播；下一episode奖励不归前条 |
| L06 | 时间上限后reset但存在合法后续状态 | 用截断前final_observation bootstrap；不使用reset后的obs；GAE不跨reset串联 |
| L07 | 死锁被定义为吸收失败 | success=False，按失败终止规则结算；不bootstrap到新episode；未完成时间标签仍缺失 |
| L08 | 软件异常、非法资源重叠 | 记录错误/违规，不把异常吞成正常done；不生成看似成功数据 |
| L09 | 完成全部任务但飞机尚未按模型完成出线 | 不提前success；如果模型定义任务完成即末站出线，需有真实出线记录 |
| L10 | 最后一步恰达到max_decisions且真实完成 | 用真实状态判定成功，不能仅因计数触顶标失败 |
| L11 | 空候选且有有效未来事件 | 推进事件而非立即死锁；空候选且无事件且仍有任务则明确诊断 |
| L12 | batch内不同环境分别终止/截断/继续 | 各自bootstrap和episode边界正确；未实现并行时标NOT_APPLICABLE |

补充：GAE的“是否允许bootstrap”和“是否接续下一条样本优势”可能需要两个掩码。不能仅把done拆成两个字段，却继续用同一个掩码处理所有情况。

## 15. M组：独立轨迹验算与短集成

**构建提示词：** 编写不调用生产环境可行性函数的日志检查器，从任务START/FINISH、正式预约修订、脉动、进出线和扰动揭示日志重建事实。排程器和检查器可以共享输入格式，不共享“已判可行”结果。

必需检查：

1. 每个任务最多实际开工一次、完成一次；完成前已开工，工时符合实际团队规则。
2. 所有任务实际开工时飞机在该站，实际加工期间不能跨脉动仍留在旧站。
3. 工人固定归属、人数、技能合法；实际加工与有效预约分别做区间检查，已取消预约不占用。
4. 对全部区间端点扫描站位容量；半开区间避免同刻释放误报。
5. 前驱实际完成不晚于后继实际开工，恢复时间不晚于实际开工。
6. 所有飞机同步脉动，当前周期保留任务及放行要求满足；出入线和驻站实体数守恒。
7. 原始基准不可变；正式历史、实际启动、后移次数与费用账本相互一致。
8. 批次全部完成且无违规才success；导出实际命中、未命中及跨架次影响。
9. 不从“累计费用低”推断可行，不从“pytest通过”替代日志审查。

| ID | 轨迹 | 验收 |
|---|---|---|
| M01 | 五站少任务手算无扰动、固定动作 | 最终时间、相对偏差与团队费用手算一致 |
| M02 | 单架受扰并后移，其他飞机不直接受扰 | 后移合法；可从日志追踪其他飞机何时因同步脉动受影响 |
| M03 | 预约父任务受扰，连锁取消并重新选队 | 所有旧事件无副作用，无工人残留占用，账本一致 |
| M04 | 故意在日志中注入重叠、重复开工、跨站加工 | 独立检查器分别抓住，证明检查器不是恒True |
| M05 | 真实283工序实例、可配置小批次无扰动 | 完整可行出线；不要求所有脉动等于qH0 |
| M06 | 真实实例、满足暖机条件的单次扰动 | 完整可行，记录实际命中；零命中不能算扰动恢复有效性验证 |
| M07 | 少量短PPO更新，含留站与后移样本 | loss/梯度有限、概率重放正确、参数更新；不要求性能提升 |
| M08 | 同一评测检查点、场景清单重复运行 | 确定性配置下结果可重复；容差与可能非确定算子明确记录 |

M06若要求五站填满并完成一个正常周期，批次数量须足够支撑该前缀；不能把只有一架飞机的实例叫作主扰动实验。小批次仍可用于其他功能验证。

## 16. N组：低成本变形测试与测试有效性检查

**构建提示词：** 在前面例子通过后，仅围绕剩余具体风险做小规模随机/变形测试。固定种子和生成规模，保存失败的最小实例。不要无上限fuzz或以随机结果替代手算。

| ID | 变形/注入 | 期望及限制 |
|---|---|---|
| N01 | 所有时间、H0、工时、恢复时间乘相同正数c，固定动作 | 可行关系不变；时间乘c；按H0归一化费用不变；绝对容差影响另行限定 |
| N02 | 整条局部时间轴和基准锚点平移c，固定动作 | 周期相对偏差不变；不要只平移实际时间却保留绝对恢复时间 |
| N03 | 随机小资源区间，与独立端点枚举oracle比较 | 容量结果一致；最早时刻可在有限事件端点集合上验算 |
| N04 | 固定已有日历，增加容量或移除占用 | 该次静态最早可行时间不变或提前；不推广到策略重跑后的全线绩效 |
| N05 | 同一有效预约多次取消/过期事件多次弹出 | 释放与费用操作幂等，不能负占用、重复退款 |
| N06 | 隔离副本临时把容量检查改回三点采样 | A01必须失败 |
| N07 | 隔离副本重新加H0硬下界/正残差ReLU | B01/H01对应失败 |
| N08 | 隔离副本把后移概率加入选队头/把截断当终止 | G07/L02对应失败 |
| N09 | 隔离副本去掉generation检查/只冻结时间头不冻结共享编码器 | E05/I05对应失败 |
| N10 | 隔离副本让评测加载随机头或重用测试训练标签 | I11/K13等契约检查失败 |

变异测试必须在隔离工作树/临时副本运行，结束后删除临时改动并确认用户工作区未被改变。若执行资源不允许，可先实施N06—N08三个高价值变异；不要报告未运行项已杀死变异。

如果仓库已有等价测试，直接扩展并记录对应ID，不为满足命名重复建文件。每个ID可以参数化多个断言，不要求“一行清单对应一个新函数”。

执行分级：

- **smoke**：各组最小反例与公式测试，CPU运行，不依赖训练权重或真实大实例。
- **integration**：跨周期/预约依赖/PPO短更新与真实实例小轨迹。只在相关单测通过后运行。
- **optional**：GPU、AMP、向量化、精确续训与跨平台。实现未声明支持时NOT_APPLICABLE；不能伪装必需项通过。
- 不预设全部测试必须在某秒数完成；先记录实际耗时，再定位明显慢例。给单个进展性测试设置合理超时用于发现死循环，不用超时替代成功判据。

命令模板（Windows PowerShell示意，实际解释器记录在报告）：

```powershell
& "D:\Conda\envs\rag_env\python.exe" -m pytest tests/work3_acceptance/test_a_resource_intervals.py -q
& "D:\Conda\envs\rag_env\python.exe" -m pytest tests/work3_acceptance -m smoke -q
& "D:\Conda\envs\rag_env\python.exe" -m pytest tests/work3_acceptance -m integration -q
```

使用marker前先在pytest配置中注册。Linux等系统用对应解释器，不复制Windows路径硬编码到测试源码。

### 最终报告必须包含

| 字段 | 内容 |
|---|---|
| 代码版本 | 修复后HEAD、工作区未提交差异说明 |
| 测试环境 | Python、torch/PyG、设备、确定性设置 |
| 规格选择 | `ADVANCE_TO_NEXT_EVENT`、暖机、失败终止、闭包限制、工时规则 |
| 测试覆盖 | 每个ID的状态、真实测试nodeid、断言目标与命令 |
| 证据 | 输出摘要、最小失败实例、种子、配置、必要日志 |
| 缺陷分类 | 实现错误 / 需求待定 / 数据缺失 / 测试错误 / 数值容差 |
| 独立可行性 | 完成率、违规明细、实际扰动命中与原始费用 |
| 未验证部分 | 不支持或尚未运行的路径，不用总体pass数掩盖 |
| 修改记录 | 本轮测试改动；若另外获准修生产代码则独立列明 |

状态含义：PASS=确实执行且满足独立断言；FAIL=执行不符合断言且已排除明显测试错误；BLOCKED=必要数据/机制未明确；NOT_RUN=尚未运行；NOT_APPLICABLE=实现及当前实验确实不包含可选功能，有说明。

### 完成门槛

1. 已确认的必需机制对应测试无FAIL/BLOCKED，关键缺陷有独立数值反例。
2. PPO概率/掩码、真实费用与塑形、标签版本及终止语义均有数值证据。
3. 至少一条真实无扰动和一条有效命中的受扰完整轨迹通过独立可行性检查。
4. 训练/验证/测试协议经清单与实际调用路径核验。
5. 未执行长训练不影响功能验收；但**功能验收通过不等于论文方法有效、泛化优越或统计显著**。
