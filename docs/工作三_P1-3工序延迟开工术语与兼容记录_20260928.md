## 设计口径

实验设计确认稿§3.1–3.4、§8规定，工作三扰动是指定飞机目标工序的开工可用性延迟。事件`e=(τ,k*,A,R)`在`τ`揭示；对命中且尚未开工的目标，将下界更新为`r_new=max(r_old,R)`，其实际开工仍须满足前驱、飞机位置、技能与工人日历、站位容量等约束。已经开工或完成的任务不撤回。它不代表共享物料、BOM、工装故障或供应链传播。

对外名称统一为“工序延迟开工（开工可用性延迟）”，英文为`task start availability delay`。实际论文可再讨论事件的工程原因；本实现不据此宣称已验证任何具体原因。

## 计划目标与实际命中的区别

| 字段 | 语义 | 产生时点 |
|---|---|---|
| `scheduled_target_count`、`scheduled_target_fraction` | 场景预先指定的目标数及其占候选数比例 | 场景生成/加载 |
| `actual_hit_count`、`actual_hit_task_keys` | 扰动发生时，目标仍在实例中且尚未开工/完成，因而确实接受事件约束的数量/集合 | 环境实际执行事件后 |
| `start_availability_advanced_count` | 实际命中且新下界严格晚于事件前旧下界的目标数 | 环境实际执行事件后 |
| `observed_start_deviation_from_baseline_hours` | 实际开工晚于基准开工的观测正偏差；不作扰动因果归因 | 轨迹完成或报告时 |

新生成但尚未执行的场景将`actual_hit_count`和`actual_fraction`置为JSON `null`。旧场景清单中的同名字段实际存放预设目标数量/比例；读取时仍兼容，但诊断器只从`affected_task_keys`还原计划目标，绝不把旧字段当作运行命中。旧文件本身未改写。

可手算例：4个候选中预设2个目标，生成阶段记录`scheduled_target_count=2`、`scheduled_target_fraction=0.5`，实际命中仍未定义。运行时如只有1个目标尚未开工且被事件命中，实际命中数为1；若`R`不晚于该任务既有下界，开工可用下界增加数仍为0。

## 兼容保留项

以下名字为机器接口兼容，不应再被解释为物料供应链机制：

- `EventType.MATERIAL_ARRIVE`：历史枚举值/事件类型，仍表示开工可用性约束事件。
- `TaskRuntimeState.material_ready_time`、轨迹记录中的`material_ready_time`及旧JSON键：历史字段名，表示工序开工可用时刻/下界。
- `material_ready_advanced_count`、`material_ready_advanced_task_keys`：运行报告兼容别名，分别等同`start_availability_advanced_count`、`start_availability_advanced_task_keys`。
- `observed_added_wait_hours`：兼容报告键，数值是目标任务相对基准的观测正偏差，并非全部由扰动导致。
- `TrajectoryFeasibilityReport.material_release`：兼容机器码，表示工序开工可用性下界约束违规。
- 旧场景清单中的`actual_hit_count/actual_fraction`：历史上分别存计划目标数/比例；新诊断迁移至`scheduled_target_*`语义，实际命中待执行后统计。

代码注释、场景元数据与新训练/评测记录均携带新名称及定义。工作二的已确认物料扰动表述、历史记录、原始三份确认稿和四份权威CSV不在本次改写范围内。静态检索若仍命中上述旧标识，仅作为兼容或历史引用；扰动生成器中“不模拟共享物料/BOM/供应链”的说明是明确排除边界。
