## 1. 核验原则

采用领域文献有明确定义或用例的概念，首次出现时给出对应英文及本研究含义。中文存在译法差异，不能把本轮选择的译法称为唯一国家标准。完整概括句是针对本研究的组合表达，不要求某篇文献曾逐字使用整个句子。

区分三类：通用学术术语；普通解释性语言；本模型专门定义的约束或变量。后两类并非禁止使用，但应直接说明含义，不包装成已获学界认可的新概念。文献证明术语与问题动机，不自动证明本方法的新颖性、实现状态或机制增益。

| 多资源约束 | resource constraints；multiple resource constraints | 按当前模型解释人员资格、人数、占用和站位并发等约束，不新增设备或空间数据 | [T1]、当前工作二模型 |
| 工序排序 | operation sequencing | 需说明策略优化候选工序的安排优先次序；给定工艺路线不改变，构造顺序不等于实际开工顺序 | [T2–T3]的任务调度背景及当前论文动作定义 |
| 站位分配 | task assignment to workstations | 决定工序分配到哪个物理站位，不是重新设计站位数量 | [T2] |
| 人员分配 | worker allocation | 通用概念；本研究具体为给定人数下的团队成员选择，并按首次使用建立站位绑定 | [T3]支持通用概念；具体规则以本模型定义为准 |
| 联合优化／联合调度 | joint optimization | 共同考虑工序、站位与人员的耦合决定；不等于已证明每个机制的独立贡献 | [T3]及当前论文 |
| 同构图／异构图 | homogeneous graph／heterogeneous graph | 前者以统一节点／边类型组织图；后者显式区分不同节点或边类型。本研究的实体属性仍可保留，具体同构实现待核 | [T4] |
| 自回归策略 | autoregressive policy | 后续选择依赖此前已作出的选择；通用方法名，不能直接作为原创性证明 | [T5]方法部分 |
| 基准排程 | baseline schedule | 扰动前已有计划π⁰，作为后续调整和偏离评价参照；也可解释为“基准调度方案” | [T6] |

| 重调度 | rescheduling | 在扰动或变化后更新已有排程。正式问题陈述优先采用该术语，解释时可说修复已有计划 | [T7]§3.1、§6.2 |
| 计划稳定性 | schedule stability | 相对已有计划的变更／偏离；本模型以开工、站位及团队变化等具体量评价，不指训练曲线稳定 | [T7]§3.4、§4及当前工作二目标 |
| 工序释放时间延迟 | 更新的最早可开工时间下界 | 对应当前工作二已知更新释放时间rᵢ；不是工序工时增加，也不自动涵盖所有资源故障 | 当前工作二§III-D |

“工序—站位—团队”可用来解释动作接口；正文涉及一般决策变量时使用“工序排序、站位分配和人员分配”，随后说明人员分配具体选择团队成员。不要把团队人数优化写入当前固定人数模型。

## 3. 原表述可以怎样收紧

| 原表述 | 建议写法 | 原因 |
|---|---|---|
| 工艺前序与多资源约束 | 工序前序约束与多资源约束 | 把约束概念写完整，并在首次出现时解释前后序关系 |
| 条件化决策 | 自回归策略；说明后续选择依赖此前选择 | 用通用方法名并解释机制 |
| 可行分配 | 约束检查与时间分配 | 直接说明实际处理，不把抽象短语当作独立方法名 |
| 类型化关系 | 不同类型的节点和边／不同关系类型 | 明确异构图具体区分什么 |
| 保留既有承诺 | 保留冻结工序及既定人员站位绑定 | 指向工作二的实际约束，避免混同工作三真实提交规则 |
| 受扰修复 | 扰动下的重调度；解释时说修复已有排程 | 优先使用领域通用术语，不擅自分类为仅调整少数受影响工序的局部重调度算法 |

本轮推荐术语已由用户确认，当前工作一、二详细资料与研究内容分配同步采用；不全局替换历史资料、已定标题或原论文。中文译法仍按本稿说明理解，模型专门定义的冻结和绑定规则保留其准确范围。

## 4. 工作一：保留定位，优化句子

**问题句草案：**在工序前序约束与多资源约束下，如何联合安排工序、站位和人员，形成可行的基准排程？

**方法与工作概括（用户确认保存的详细版）：**面向飞机脉动装配线的工序前序约束与多资源约束，采用同构图表示调度状态，通过自回归策略联合进行工序排序、站位分配和人员分配，构造可行的基准排程。

末尾保留用户认可的“构造可行基准排程”。正式技术路线再说明掩码和时间分配怎样满足约束；不把人员占用、绑定或排序中的某一个预排为最重要因素。该句不是更改工作一题名。

## 5. 工作二：研究问题与完整概括分开

前轮问题句有助于递进，但不足以独自承担整项工作的介绍。研究问题说明待解决的困难与评价目标；完整概括还须说明异构表示、联合调度及受扰重调度，不把方法名字全部塞进问题句。

**研究问题（当前保留的详细版）：**工序释放时间延迟后，如何在冻结工序和人员站位绑定约束下，对已有基准排程进行重调度，兼顾完工时间与计划稳定性？

**完整工作概括（按用户选定的方案A保留详细版）：**采用工序、站位、人员和技能构成的异构图表示调度状态，研究工序排序、站位分配与人员分配的联合调度方法；进一步结合基准排程及扰动后更新的工序释放时间，在冻结工序和人员站位绑定约束下进行重调度，兼顾完工时间与计划稳定性。

完整概括保留当前工作二稿的无扰动联合调度基础和受扰重调度，不把两者写成两项独立学位工作。工作一完整展开共同联合动作；工作二重心仍是异构表示及基准条件下的稳定重调度。用户已选定两部分并列展示的组织方案；详细概括先保存，开题正文与口头版本随后精简，不宣称新代码已实现。

“完工时间”具体对应当前论文的模板跨度指标；开题展开时须注明层级，不能解释为整批飞机实际工期。“计划稳定性”需接到具体偏离指标，不能用综合分数优势替代各分量结论。

## 6. 下一步优先建立的对照

| 层次 | 工作一 | 工作二 |
|---|---|---|
| 研究问题 | 前序与资源约束下的联合基准构造 | 更新释放时间后，效率与计划稳定性的重调度权衡 |
