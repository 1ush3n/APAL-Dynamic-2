## 4. 优先修复的明确差异

### R01 / P0：完整层级工艺依赖没有贯通工作三入口

**设计要求。** 保留完整DAG，或从完整DAG生成保持物理Task前序可达关系的等价投影；不能删虚拟节点后只保留Task行显式紧前。

**代码事实。** [utils/work3/multi_aircraft_baseline.py:283–298](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/utils/work3/multi_aircraft_baseline.py#L283-L298)直接解析CSV显式紧前；[utils/work3/multi_aircraft_baseline.py:324–348](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/utils/work3/multi_aircraft_baseline.py#L324-L348)按正工时筛选模板。工作三环境_load_domain_metadata也重新读显式紧前，没有调用通用加载器生成层级边。图构造器再仅连接仍存在于物理任务映射内的前序。

**实际核对。** 对data/283.csv执行仓库data_loader.py原有层级构图步骤，得到290个节点、283个物理Task、753条完整DAG边。从中枚举内部全为虚拟节点的物理端点路径，得到27,238个投影端点对；当前首架飞机模板只有47条前序边，其中27,191个投影端点对在该模板中不存在可达路径。这里统计的是“可达关系缺失”，不表示必须新增27,191条不可约边；可用保持可达性的紧凑图表示。

例如AAQS00-0010→A-2→A-4→A-6→ARHS00-0160的物理前序联系未传入当前物理模板。原始图无环已用标准库拓扑排序复核。

**影响。** 时间预约、后移合法性、图消息传播以及独立验收可能共用不完整工艺依据；即使在当前模板上显示“合法”，也不能据此认定满足完整工艺DAG。

**修复与验收。** 统一完整DAG入口，生成物理投影或保留虚拟节点；同步基线生成、环境、图和独立验收。用跨Sub路径、分支汇合、所有物理后继及可达关系一致性验收。已有基线需重新核验，本轮没有证明某条完整实际生产轨迹已违反这些缺失依赖。

### R02 / P0：未开工预约仍可主动改派；扰动还会抹掉已提交决定

**设计要求。** 提交后站位、团队、对齐不可主动更改；新扰动只使固定决定被动顺延，不能重新选队。

**代码事实。** [envs/work3/environment.py:441–473](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/envs/work3/environment.py#L441-L473)允许RESERVED且尚未实际开工的任务再次成为候选。step留站分支主动释放旧日历、重新选队并重算时间；_handle_disturbance_event调用cancel_reservation，后者清空assigned_team、scheduled_start、execution_duration，再开放选择。见[envs/work3/environment.py:1177–1195](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/envs/work3/environment.py#L1177-L1195)和core_types.py:204—211。

**复现。** 真实任务0_15预约于20时，仍在动作候选中，分支掩码为(True, False)。在1时揭示新可开工下界30后，原团队[12,72]变为空列表，任务退为UNREADY，can_reserve仍为True。

**修复与验收。** 分开保存不可撤回决定与可变的可行执行时间；保存align。已提交任务退出新决策候选。扰动及前驱传播只能为同一站位/团队/对齐重排必要时间区间，旧计时事件可以失效，但决定不能清空。分别验收直接受扰、后继受影响和资源链顺延。

现有test_work3_f08_reservation_revision.py:110起明确要求“预约可重选团队”，是旧合同测试，应随新规则改写。

### R03 / P0：严格同刻的开工—扰动顺序与确认相反

**设计要求。** 对此前已有效提交、满足条件的预约，实际开工与扰动严格同刻时先开工；刚开工任务不受本次开工限制影响。

**代码事实。** [envs/work3/event_queue.py:25–39](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/envs/work3/event_queue.py#L25-L39)设置DISTURBANCE=2，TASK_START=5，扰动优先。

**复现。** 任务0_6有效预约开工时刻为0.5457256030603916，在完全相同时间施加扰动后，它变为UNREADY，actual_start仍为None，团队被清空。

**修复与验收。** 在符合已揭示前驱、资源、开工下界的前提下处理有效实际开工，再揭示扰动；不能只调换枚举就跳过失效事件和条件复核。验证τ之前、严格同刻、τ之后，以及旧generation失效的案例。现有test_work3_same_timestamp_events.py中test_same_timestamp_disturbance_invalidates_start_before_execution正验证旧顺序。

## 5. 语义增强主线的缺口

### R04 / P1：分层融合没有按“飞机—站位当前/下一周期—整线”实现

**设计要求。** 完整图编码后，对未完物理任务按飞机及当前/紧邻下一/更后角色读出，形成站位当前与下一周期摘要，再用MLP融合；候选评分读取自身飞机、源站当前、目标站下一周期和整线表示。

**代码事实。** [models/work3/actor_critic.py:148–163](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/models/work3/actor_critic.py#L148-L163)只对task/worker/station/skill分别做全局mean_pool，再拼接MLP。在线上下文还有32维人工状态分支。候选使用工序嵌入和一个全局上下文，未见已确认的飞机分组及分层读出接口。

图里已有当前/未来负荷标量，不能说完全没有这些信息。但[models/work3/graph_builder.py:394–421](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/models/work3/graph_builder.py#L394-L421)把不在目标站实际加工的所有后续任务都加到station_future_workload；它代表所有后续负荷，不是仅下次脉动进入该站的飞机。[models/work3/graph_builder.py:488–499](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/models/work3/graph_builder.py#L488-L499)将此数值写入站位特征。

**修复与验收。** 明确current/next/further派生集合；编码完整图，读出排除已完及虚拟节点；下一周期集合只选下次实际进入本站的飞机，加入已正式后移任务并去重。保留更后工艺上下文，但不要把它混作next。同刻新决定、完成、后移、真实脉动和纯时间推进均要刷新。

### R05 / P1：只有当前周期标量头，缺下一周期各站预测与首次就绪事实

**设计要求。** 当前残差加下一周期5站有符号向量；下一目标为(F[m,q+1]−P[q]−H0)/H0，并有占用/有效性掩码。空站无效，有飞机但无任务仍有效。F为首次实际就绪时刻，可能由最后一次合法后移解除未完任务而形成。

**代码事实。** [models/work3/time_head.py:40–56](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/models/work3/time_head.py#L40-L56)最后输出Linear(32,1)。Actor的time_fusion time_dim=2，只处理由当前残差得到的两个时间特征；没有下一周期5站预测和占用输入。MultiAircraftState有transfer_history，AircraftRuntimeState有实际进出站时刻，但未见按周期记录的各站首次就绪账本。布尔is_station_cleared_for_transfer不能替代F。

**修复与验收。** 先补首次就绪事件与一次锁定账本，再加有符号站位头、占用标记和监督掩码，接入分层表示与候选评分。不能用全线共同转站时刻代替所有站的就绪时刻，也不能对无结果目标填零。

### R06 / P1：冻结副本只供塑形，Actor预测输入仍取在线模型

**设计要求。** 网络方案B要求完整轨迹内固定预测副本同时为Actor提供显式当前/下一预测特征；在线Actor和共享表征仍可训练。

**代码事实。** PotentialRewardShaper已有完整冻结Actor/当前时间头。可是[scripts/work3/train_ppo_work3.py:593–624](https://github.com/1ush3n/APAL-Dynamic-2/blob/130aa49e350ecb86dd37d9b9c07176691d8cff84/scripts/work3/train_ppo_work3.py#L593-L624)直接调用传入的在线actor_critic和time_head生成Actor时间输入；采样循环1288—1298行也传入在线对象。轨迹跨PPO更新后，动作使用的预测路径会变化，塑形路径仍按固定版本。

**修复与验收。** 将副本抽为共同预测服务，按episode版本提供Actor数值与当前势函数；每个新状态仍重算预测。保存当前/下一特征、占用、版本并用于PPO重放。现有保存time_urgency的实现值得保留；本条不等于声称现有PPO一定无法复算旧概率，问题是决策输入不符合已选方案B。

### R07 / P1：历史标签只完成单目标生命周期

**设计要求。** 每个完整决策保存可重编码历史输入；P[q]回填当前项，P[q+1]回填下一项；当前项已训练仍保留未来项需要的快照，分别管理待结算/可用/无效。

**代码事实。** PendingTimeLabel与attach_transfer只管理当前残差；attach_transfer直接pop周期记录，drain_ready取走后清空。现有跨采样段等待与快照克隆已实现，但无法承载“当前标签已结算、下一标签仍待结算”。也未见状态采集与标签结算训练版本跨度的完整记录；predictor_version主要来自塑形副本版本，不能代替Actor更新版本。

**修复与验收。** 共享不可变历史输入，给两目标独立状态、掩码及结果账本；记录采集/结算版本与峰值内存。近期辅助采样和预算控制需落地，具体容量与年龄阈值仍是实施参数，不能虚构为用户已指定数值。

### R08 / P2：最近事件/决定的变化摘要没有显式输入

**设计要求。** 当前完整状态加最近真实变化，不要求递归记忆网络。

**代码事实。** 图和32维状态主要表达当前执行、预约、发布参照、资源和周期；未见最近事件类型、受影响对象及变化量的独立快照与编码契约。last_published_assignment是当前参照，不等同最近发生了什么。

**修复与验收。** 在事实快照中补最近变化及版本，随历史输入保存；明确其粒度，不擅自加入LSTM或人工情景标签。本条为静态链路核对，未运行表示区分实验。
