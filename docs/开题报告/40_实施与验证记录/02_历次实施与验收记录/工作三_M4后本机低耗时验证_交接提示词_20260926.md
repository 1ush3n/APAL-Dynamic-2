### L1：修复零费用基线的评测百分比口径（纯单测，优先）

**问题：** 当前 `scripts/work3/evaluate_c_vs_d.py::compare_c_vs_d_pair()` 在双方完整、独立可行而 `J_total(C) <= 1e-6` 时，直接报告 `improvement_j_total_pct=0.0`。当 C 的费用为零或接近零时，百分比没有可靠分母；即使 D 费用增加，也不应报告“改善 0%”。此外，现有 `summarize_benchmark_credibility()` 的 `valid_comparison_count` 实际只数有百分比的配对，可能与物理上有效的完整配对数量混淆。

**修改：** 对双方已完工且可行的配对，总是保留 `cost_delta_j_total = J_total(C) - J_total(D)` 及双方原始费用。只有 C 的费用大于事先明确定义的分母阈值时才算百分比；否则设百分比 `None`，状态标记为“完整且可行，但百分比分母不足”。分开统计 `completed_feasible_pair_count` 与 `percentage_eligible_pair_count`，原有 `valid_comparison_count` 若外部调用依赖其语义，应兼容或清楚迁移，不把已完工零费对算为物理失败。**不要**用 `0.0` 或 `NaN` 代替不可定义值。检查 `j_total` 缺失是否被静默当成 0；缺失应标记数据不完整。

**反例与验收：** 在相应评测测试文件加参数化测试：`C=0,D=0`、`C=0,D>0`、`0<C<=阈值,D>=0`、`C=10,D=8`、`C=10,D=12`、`C/D 非有限`、一方未完工或独立不可行、双方暖机前缀不一致、缺少费用字段。断言原始费用差、百分比、状态和两类计数分别正确；已有有效正常配对数不减少。只运行新文件和受影响的评测单测，不跑完整评测脚本。预计数秒到约一分钟。
