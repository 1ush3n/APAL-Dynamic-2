## 5. 六级决策分层对比实验深度剖析 (E0 到 E5)

基于 `work3_4060/diagnostics/diag_e0_e5_comparison.py`，严格按照分层递进协议测试各级决策自由度对性能的影响：

```
E0: 原始基线 (固定团队 + 固定次序 + 同步移位)   -> Makespan: 525.882h, St3: 52.038h
E1: 仅工序重排 (固定团队不变)                  -> Makespan: 525.882h, St3: 52.038h (0.00h 改善!)

E5: 取消同步，完全异步工位拉动流 (Pull Line)    -> Makespan: 404.781h, St3: 49.442h (-121.10h Makespan!)
```

### 5.1 为什么 E1 (仅重排序) 无法产生任何改善？
- 在 Baseline 中，工序 12、13 与工序 27 均被分派给了同一个预设团队 `[0, 66]`。
- 无论如何改变就绪队列中工序的先后次序，由于工人 0 和 66 既要做工序 12 (1.63h)、工序 13 (0.97h)，又要做工序 27 (49.44h)，该团队的累积串行工时严格等于：
  $$1.628 + 0.968 + 49.442 = 52.038\text{h}$$
- **结论**：若不改变固定组队，单纯调度工序优先级的决策空间收益为 **0.000h**。

### 5.2 为什么 E2 (联合重组队) 能瞬间突破瓶颈？
- Station 3 共有 6 名工人 (`[0, 47, 50, 51, 66, 76]`)。其中全员均具备技能 0，但具备技能 4 的只有 Worker 0 和 Worker 66。
- E2 优化解将技能 0 的工序 12、13 分流给团队 `[47, 76]` 或 `[47, 50]`，使得全站唯一的技能 4 资质团队 `[0, 66]` 在 $t=0.0\text{h}$ **专职开工 Task 27**。
- Task 27 在 $t=49.442\text{h}$ 准时完工，站位 3 清空时间从 52.038h 缩短到 49.442h (-2.595h)，达成理论最优极限。

### 5.3 为什么 E3 (跨站后移) 在 mini210 中无法生效？
- mini210 中唯一造成节拍延误的工序是 Station 3 的 Task 27 (需技能 4)。
- 然而在 `resources.json` 配置中，**Station 4 仅配置了 2 名工人 (`[6, 55]`)，且两人技能均为技能 0 与技能 1，完全不具备技能 4** (`skill_4_count = 0`)。
- 环境状态机在执行后移合法性检查时，检测到下游站位物理无法承接，强制硬阻断后移。因此 E3 无法在此场景中提供额外收益。

## 11. 约束松弛与机理消融结论 (Constraint Relaxation)

### 11.1 站位并发限制 ($\le 3$) 的松弛结论
- **实验设置**: 将每个站位允许同时加工的工序数上限从 3 放宽至 $\infty$。

  - 站位 3 清空时间：保持 52.037844h (变化 0.000h)。

### 11.2 同步移位约束的松弛结论 (脉动同步 vs 异步拉动)

- **机理解释**:
  - 站位 1 (14.2h)、站位 2 (8.2h)、站位 4 (12.5h)、站位 5 (4.1h) 的完工速度远快于站位 3 (49.4h)。

### Q1: 站位 3 的 49.44h / 52.04h 线索到底是否成立？
**权威裁决：完全成立**。
- **数学下界证明**：站位 3 包含工序 27（需 2 名技能 4 工人，标称 50.1h）。站内最高效技能 4 团队为 Worker 0 (eff=1.110) 与 Worker 66 (eff=1.109)，协同因子为 0.917，实际最短物理加工工时为：
  $$p_{27}^{\min} = \frac{50.10 \times 2}{(1.10958 + 1.10943) \times 0.917} = 49.442368\text{h}$$
- **失误因果链**：规则基线在分派时依据 `task_id` 升序，先分派了 Task 12 和 13，选走了 Worker 0 和 66，导致 Task 27 被推迟 2.595h 开工，清空时间变为 $2.595 + 49.442 = 52.038\text{h}$。站内重组团队消除抢占后，站位 3 清空时间严格收敛至 **49.442368h**，Optimality Gap 严格为 **0.00%**。

### Q2: 现有规则基准到底是不是最优的？
**权威裁决：绝对不是最优**。
- 规则基准存在系统性贪心排序缺陷。除站位 3 外，站位 2 的 Task 26（技能 4，8.18h）同样被次要工序抢占 Worker 22，导致开工推迟 2.215h，站位 2 清空时间被人为垫高至 10.393h（下界仅为 8.178h，Gap 达 21.31%）。规则基准在站位 2 和站位 3 上均存在显著且容易修复的次优调度。

### Q3: 站内调整、后移、对齐等待，各自有多少真实空间？
**权威裁决**：
1. **站内调整 (E2)**：**存在巨大有效空间**。通过站内工种分流与团队重组，可直接消除 2.595h 饥饿，将瓶颈站位压缩至理论极限 49.442h。但纯工序重排序 (E1) 若不重组团队，收益为 0。
2. **跨站后移 (E3)**：**在当前 mini210 配置中收益为 0**。因为唯一需要后移的瓶颈工序 Task 27 需要技能 4，而下游站位 4 的 2 名工人全无技能 4，被物理硬阻断；其余工序富余时间充足，无需后移。
3. **对齐等待 (Align Mode)**：**属于关键的人为解空间屏障**。若使用 `align: 1`，环境将开工时刻强制死锁在历史偏移量上，无法释放任何提前开工收益；必须使用 `align: 0` (ASAP 紧凑模式) 方可解锁全部优化潜力。

### Q4: 标称节拍 $H_0$ 是物理极限还是设计参数？
**权威裁决：是包含算法失误的人为设计参数，而非物理极限**。
- 真正的物理极限是 49.442h。
- 若仅优化站位 3 调度，但生产线设计参数 $H_0$ 仍保持为 52.038h，则在 `nominal_anchored_v1` 同步体制下，由于每个脉动周期末尾强制等待至 $q \times 52.038\text{h}$，**7 机总工期改善严格为 0.000h**（时钟掩盖效应）。

### Q5: 7 机、20 机、50 机，规律是否一致？
**权威裁决：完全一致，且工期收益随生产批量线性放大**。
